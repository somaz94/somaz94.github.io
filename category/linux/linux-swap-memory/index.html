    Linux Swap Memory Complete Guide: Understanding Virtual Memory

    How swap space extends physical RAM and keeps systems stable under memory pressure


    Overview

    Linux swap memory is disk space used when physical RAM (Random Access Memory) is fully utilized. It acts as an overflow area for RAM, allowing the operating system to continue functioning even when available physical memory is insufficient for all running applications and processes.


    What is Swap Memory?

    Swap space is a portion of a storage drive (e.g., SSD or HDD) reserved to extend the system’s memory capacity.

    While slower than actual RAM due to disk I/O operations, it provides a fallback mechanism when RAM becomes overcommitted.


    Visual Representation

    ┌─────────────────────────────────────┐
│        Physical RAM (Fast)          │
│  ┌──────────────────────────────┐  │
│  │   Active Programs & Data     │  │
│  └──────────────────────────────┘  │
└─────────────────────────────────────┘
              ↓ ↑ (Swapping)
┌─────────────────────────────────────┐
│       Swap Space (Slower)           │

│  │  Inactive Memory Pages       │  │
│  └──────────────────────────────┘  │
└─────────────────────────────────────┘


    How Swap Works


    The Swapping Process

    When RAM fills up:

    1. Paging Out (Swap Out): 
      RAM Full → Kernel identifies inactive memory pages
           ↓
        Moves pages to swap space
           ↓
        Frees RAM for active processes
    2. Paging In (Swap In): 
      Swapped data needed → Kernel retrieves from swap
                      ↓
                   Loads back to RAM
                      ↓
                   May swap out other data


    Example Scenario

    Scenario: 4GB RAM system running multiple applications

Initial state:
RAM: [Browser][Editor][Music][Email] = 3.8GB used

User opens video editor:
RAM needed: 4.5GB (exceeds 4GB!)

System response:
1. Identifies inactive pages (e.g., Email in background)
2. Swaps Email data to disk (500MB)
3. Loads Video Editor into freed RAM
4. Total RAM used: 3.8GB, Swap used: 500MB

User switches to Email:
1. Email data swapped back in
2. Music player swapped out if needed


    Types of Swap


    1. Swap Partition

    Definition: Dedicated disk partition exclusively for swap space

    Characteristics:

    • More efficient (no filesystem overhead)
    • Fixed size (requires repartitioning to change)
    • Traditional approach

    Creating Swap Partition:

    # List disks
lsblk

# Create partition (using fdisk)
sudo fdisk /dev/sdb
# Commands in fdisk:
# n (new partition)
# p (primary)
# Enter (default start)
# +2G (2GB size)
# t (change type)
# 82 (Linux swap)
# w (write changes)

# Format as swap
sudo mkswap /dev/sdb1

# Enable swap
sudo swapon /dev/sdb1

# Make persistent
echo '/dev/sdb1 none swap sw 0 0' | sudo tee -a /etc/fstab


    2. Swap File

    Definition: Regular file on existing filesystem used for swapping

    Characteristics:

    • Easier to create and resize
    • No repartitioning needed
    • Slightly less efficient due to filesystem layer

    Creating Swap File:

    # Method 1: Using fallocate (faster)
sudo fallocate -l 2G /swapfile

# Method 2: Using dd (more compatible)
sudo dd if=/dev/zero of=/swapfile bs=1M count=2048

# Set correct permissions
sudo chmod 600 /swapfile

# Format as swap
sudo mkswap /swapfile

# Enable swap
sudo swapon /swapfile

# Make persistent
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# Verify
sudo swapon --show
free -h


    Comparison Table

    Feature Swap Partition Swap File
    Performance Slightly faster Slightly slower
    Flexibility Fixed size Easy to resize
    Setup Requires partition Simple file creation
    Management Harder to change Easy to modify
    Efficiency No FS overhead Minor FS overhead

    Configuring Swap


    Creating Swap File (Complete Guide)

    #!/bin/bash
# create-swap.sh - Create and configure swap file

# Configuration
SWAP_SIZE="2G"
SWAP_FILE="/swapfile"
SWAPPINESS=10

echo "Creating ${SWAP_SIZE} swap file..."

# 1. Create swap file
sudo fallocate -l ${SWAP_SIZE} ${SWAP_FILE}

# 2. Set permissions
sudo chmod 600 ${SWAP_FILE}

# 3. Format as swap
sudo mkswap ${SWAP_FILE}

# 4. Enable swap
sudo swapon ${SWAP_FILE}

# 5. Make permanent
if ! grep -q "${SWAP_FILE}" /etc/fstab; then
    echo "${SWAP_FILE} none swap sw 0 0" | sudo tee -a /etc/fstab
fi

# 6. Set swappiness
sudo sysctl vm.swappiness=${SWAPPINESS}
if ! grep -q "vm.swappiness" /etc/sysctl.conf; then
    echo "vm.swappiness=${SWAPPINESS}" | sudo tee -a /etc/sysctl.conf
fi

# 7. Verify
echo "Swap configuration complete!"
sudo swapon --show
free -h


    Resizing Swap File

    # Disable current swap
sudo swapoff /swapfile

# Remove old swap file
sudo rm /swapfile

# Create new larger swap file
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# Verify
free -h


    Removing Swap

    # Disable swap
sudo swapoff /swapfile

# Remove from fstab
sudo sed -i '/swapfile/d' /etc/fstab

# Delete swap file
sudo rm /swapfile

# Verify
free -h


    Swappiness Parameter


    What is Swappiness?

    Swappiness is a kernel parameter (0-100) controlling how aggressively the system uses swap.

    Value Range: 0 - 100

0   = Avoid swapping except absolutely necessary
10  = Minimal swapping (recommended for desktops/SSDs)
60  = Default Linux behavior
100 = Aggressive swapping


    How It Works

    Low swappiness (0-10):

    Behavior: Keep data in RAM as long as possible
Use case: Desktop systems, databases, high-performance servers
Trade-off: Risk of OOM (Out of Memory) if RAM fills up

    Default swappiness (60):

    Behavior: Balanced approach
Use case: General-purpose servers
Trade-off: Some swap usage even with available RAM

    High swappiness (80-100):

    Behavior: Swap aggressively to keep RAM free
Use case: Systems with slow RAM or specific workloads
Trade-off: Frequent disk I/O, slower performance


    Checking Current Swappiness

    # View current value
cat /proc/sys/vm/swappiness
# Output: 60 (default)

# Or using sysctl
sysctl vm.swappiness
# Output: vm.swappiness = 60


    Changing Swappiness

    Temporary (until reboot):

    sudo sysctl vm.swappiness=10

    Permanent:

    # Edit sysctl.conf
sudo nano /etc/sysctl.conf

# Add or modify:
vm.swappiness=10

# Apply changes
sudo sysctl -p


    Recommended Values

    System Type Swappiness Reason
    Desktop with SSD 10 Reduce SSD wear, keep responsive
    Server with database 1-10 Keep database in RAM
    General server 30-60 Balanced approach
    Low RAM system 60-80 Prevent OOM
    Embedded/IoT 10-30 Limited disk I/O


    Advantages of Swap


    1. Prevents Out-of-Memory (OOM) Errors

    Without swap:

    RAM full → Kernel kills processes (OOM Killer) → Service disruption

    With swap:

    RAM full → Inactive data moved to swap → System continues running


    2. Hibernation Support

    Hibernation requires:

    Swap size ≥ RAM size

Process:
1. Save entire RAM to swap
2. Power off system
3. On resume: Restore RAM from swap


    3. Improved Stability

    Memory overcommit protection:

    Application requests more memory than available
→ Swap provides buffer
→ Critical processes stay alive


    Disadvantages of Swap


    1. Slower Performance

    Speed comparison:

    RAM access:    ~10-100 ns
SSD swap:      ~50-150 μs  (500-1500x slower)
HDD swap:      ~5-10 ms    (50,000-100,000x slower)

    Heavy swapping (thrashing):

    System spends more time swapping than executing
→ Severe performance degradation
→ System appears frozen


    2. SSD Wear

    Write amplification:

    Frequent swap writes → Reduced SSD lifespan

Example with heavy swapping:
Daily swap writes: 50GB
SSD write endurance: 150TBW (typical 500GB SSD)
Lifespan reduction: ~8 years → ~6 years

    Mitigation:

    • Lower swappiness (reduce swap usage)
    • Use swap file on HDD if available
    • Monitor swap usage


    3. Latency

    Impact on applications:

    Database query accessing swapped data:
Normal: 1ms
With swap: 50-100ms (50-100x slower)


    Best Practices


    1. Swap Size Recommendations

    RAM Size Swap Size (With Hibernation) Swap Size (Without Hibernation)
    < 2GB 2x RAM 1x RAM
    2-8GB 1x RAM 0.5x RAM
    8-64GB 0.5x RAM 4-8GB
    > 64GB 4-8GB 2-4GB


    2. Monitor Swap Usage

    # Create monitoring script
cat > /usr/local/bin/check-swap.sh <<'EOF'
#!/bin/bash
SWAP_USED=$(free -m | awk '/Swap:/ {print $3}')
SWAP_TOTAL=$(free -m | awk '/Swap:/ {print $2}')

if [ $SWAP_TOTAL -gt 0 ]; then
    SWAP_PERCENT=$((SWAP_USED * 100 / SWAP_TOTAL))
    
    if [ $SWAP_PERCENT -gt 50 ]; then
        echo "WARNING: Swap usage at ${SWAP_PERCENT}%"
        # Send alert (email, slack, etc.)
    fi
fi
EOF

chmod +x /usr/local/bin/check-swap.sh

# Add to crontab
(crontab -l 2>/dev/null; echo "*/5 * * * * /usr/local/bin/check-swap.sh") | crontab -


    3. SSD-Specific Configuration

    # Reduce swappiness for SSDs
echo "vm.swappiness=10" | sudo tee -a /etc/sysctl.conf

# Reduce cache pressure
echo "vm.vfs_cache_pressure=50" | sudo tee -a /etc/sysctl.conf

# Apply
sudo sysctl -p


    4. Set Up Alerts

    # Install monitoring tools
sudo apt-get install sysstat

# Monitor swap I/O
sar -W 1 10  # Check swap statistics

# Set up alert thresholds
# Alert if swap usage > 80%
# Alert if si/so (swap in/out) > 1000 pages/sec


    Troubleshooting


    Issue 1: System Running Slow (Thrashing)

    Symptoms:

    • System extremely slow
    • High disk I/O
    • swap in/out very high

    Diagnosis:

    # Check swap activity
vmstat 1

# Look for:
# si (swap in) and so (swap out) > 0
# High values indicate thrashing

    Solution:

    # 1. Add more RAM (best solution)

# 2. Reduce swappiness
sudo sysctl vm.swappiness=10

# 3. Identify memory-hungry processes
ps aux --sort=-%mem | head -10

# 4. Kill or optimize heavy processes


    Issue 2: Swap Not Activating

    Check if enabled:

    sudo swapon --show
# If empty, swap is not active

    Solutions:

    # 1. Check fstab entry
cat /etc/fstab | grep swap

# 2. Manually enable
sudo swapon -a

# 3. Verify swap file exists and has correct permissions
ls -lh /swapfile
# Should be: -rw------- (600)


    Issue 3: Cannot Create Swap File

    Error: fallocate failed:

    # Some filesystems don't support fallocate
# Use dd instead:
sudo dd if=/dev/zero of=/swapfile bs=1M count=2048


    Conclusion

    Linux swap memory serves as an extension of physical RAM, helping systems remain stable even under memory pressure.

    While swap performance is lower than RAM, it acts as a critical safety net during memory overflow situations, enhancing system stability and flexibility.


    Key Takeaways

    ✅ Swap prevents OOM: System stays alive when RAM fills
    ✅ Choose type wisely: Partition for performance, file for flexibility
    ✅ Tune swappiness: Lower for SSDs/desktops, higher for low-RAM systems
    ✅ Monitor usage: Watch for thrashing (excessive swapping)
    ✅ Consider SSD wear: Minimize unnecessary swap writes


    Decision Guide

    When to use swap:

    • Systems with limited RAM
    • Servers running variable workloads
    • Systems requiring hibernation
    • Protection against memory spikes

    When swap may not be needed:

    • Systems with abundant RAM
    • Performance-critical applications
    • Databases (should stay in RAM)
    • Modern desktops with 16GB+ RAM


    Proper swap configuration matched to your system environment reduces memory shortage risks and ensures better performance and stability.
