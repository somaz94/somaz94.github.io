    Migrating from Docker Desktop to OrbStack on macOS

    A complete step-by-step guide to replacing Docker Desktop with a lightweight, high-performance alternative


    Overview

    Running Docker Desktop on macOS often leads to excessive CPU usage, spinning fans, and sluggish system performance — especially during image builds. These issues are not merely inconvenient; they directly impact developer productivity and hardware longevity.

    OrbStack is a native macOS alternative to Docker Desktop, built with Swift and designed for minimal resource consumption. It provides full Docker CLI compatibility, meaning existing commands like docker, docker compose, and docker buildx work without any modification.

    This guide walks through the complete migration process from Docker Desktop to OrbStack, including pre-migration checks, step-by-step instructions, verification procedures, and real-world performance comparisons.


    What is OrbStack?

    OrbStack at a Glance
    • Startup Time: Approximately 2 seconds (vs 20-30 seconds for Docker Desktop)
    • Idle CPU Usage: Around 0.1% (vs 3-5% for Docker Desktop)
    • Docker CLI Compatibility: 100% drop-in replacement
    • Automatic Migration: Containers, images, volumes, and daemon config
    • Built-in Kubernetes: Native K8s support included
    • Linux VM Management: Run Ubuntu, Fedora, and other distributions


    Performance Comparison: Docker Desktop vs OrbStack

    Metric Docker Desktop OrbStack Improvement
    Startup Time 20–30 seconds ~2 seconds ~10x faster
    Idle CPU Usage 3–5% ~0.1% Near zero
    Idle Power Draw 726mW 180mW ~4x more efficient
    Image Build Speed Baseline ~1.2x faster ARM64/AMD64 builds
    Filesystem Performance Baseline ~1.3x faster Small file I/O
    Memory Usage High (VM overhead) Low Noticeable difference
    Battery Consumption High ~1.7x more efficient Significant on laptops

    Source: OrbStack Official Benchmarks, OrbStack vs Docker Desktop


    Pre-Migration Preparation


    Check Current Docker Status

    Before migrating, verify your current Docker Desktop environment.

    Example output:

    Client:
 Version:           27.4.0
 OS/Arch:           darwin/arm64
 Context:           desktop-linux

Server: Docker Desktop 4.37.2 (179585)

    DRIVER    VOLUME NAME
local     docker_db_data
local     docker_ghost_data
local     ghost_db_data
local     ghost_ghost_data
...


    Backup Critical Volumes (Recommended)

    Migration typically completes without issues, but backing up important volumes beforehand is a prudent precaution.


    Migration Process

    graph LR A[Install OrbStack] --> B[Quit Docker Desktop] B --> C[Launch OrbStack] C --> D[Run Migration] D --> E[Verify Results] E --> F[Clean Up CLI] F --> G[Remove Docker Desktop]


    Step 1: Install OrbStack

    Install OrbStack via Homebrew.

    brew install --cask orbstack

    Expected output:

    ==> Installing Cask orbstack
==> Moving App 'OrbStack.app' to '/Applications/OrbStack.app'
==> Linking Binary 'orbctl' to '/opt/homebrew/bin/orbctl'
==> Linking Binary 'orb' to '/opt/homebrew/bin/orb'
🍺  orbstack was successfully installed!


    Step 2: Quit Docker Desktop

    Running both simultaneously can cause conflicts, so Docker Desktop must be stopped first.

    # Quit from terminal
osascript -e 'quit app "Docker Desktop"'

# Or click Docker icon in menu bar → Quit Docker Desktop


    Step 3: Launch OrbStack

    open -a OrbStack

    Wait for the initial setup to complete, then verify the status.

    orb status
# Running


    Step 4: Migrate Docker Desktop Data

    Once OrbStack is in the Running state, execute the migration.

    orb docker migrate
    ⚠️ Note: Earlier versions used orb migrate docker, which is now deprecated. Use orb docker migrate instead.


    Migration log example:

    The following items are automatically migrated:

    • Docker images
    • Docker volumes
    • Docker containers
    • Daemon configuration (insecure-registries, etc.)
    💡 BuildKit Container Failure

    BuildKit containers may fail to migrate due to image compatibility issues. This is expected behavior — docker buildx will automatically recreate them on first use.


    Step 5: Verify Migration

    Check Docker Context

    docker context ls

    NAME            DESCRIPTION                               DOCKER ENDPOINT                                 ERROR
default         Current DOCKER_HOST based configuration   unix:///var/run/docker.sock
desktop-linux   Docker Desktop                            unix:///Users/somaz/.docker/run/docker.sock
orbstack *      OrbStack                                  unix:///Users/somaz/.orbstack/run/docker.sock

    Confirm that orbstack * is the active context.


    Check Docker Version

    docker version

    Client:
 Version:           28.5.2
 OS/Arch:           darwin/arm64
 Context:           orbstack

Server: Docker Engine - Community
 Engine:
  Version:          28.5.2


    Verify Volumes

    docker volume ls

    Ensure all previously existing volumes are present.


    Verify Daemon Configuration

    docker info 2>&1 | grep -A5 "Insecure Registries"

    Insecure Registries:
  harbor.somaz.link
  ::1/128
  127.0.0.0/8

    Confirm that insecure registries and other daemon settings have been preserved.


    Test a Docker Build

    cd your-project
docker build --no-cache -t test-build .

    Verify that the build completes successfully.


    Verify kubectl Connectivity (If Applicable)

    kubectl cluster-info

    Confirm that existing Kubernetes cluster connections remain intact.


    Step 6: Clean Up Docker Desktop CLI

    Verify that CLI tools point to OrbStack rather than Docker Desktop.

    which docker
ls -la /usr/local/bin/docker
ls -la /usr/local/bin/docker-compose
ls -la /usr/local/bin/docker-credential-desktop

    Expected output:

    /usr/local/bin/docker -> /Applications/OrbStack.app/Contents/MacOS/xbin/docker
/usr/local/bin/docker-compose -> /Applications/OrbStack.app/Contents/MacOS/xbin/docker-compose

    If docker-credential-desktop still points to Docker Desktop, remove it.

    sudo rm -f /usr/local/bin/docker-credential-desktop


    Step 7: Uninstall Docker Desktop (Optional)

    After several days of stable OrbStack usage, Docker Desktop can be safely removed.

    brew uninstall --cask docker
    💡 Tip

    Consider running both side-by-side for a few days before removing Docker Desktop. Use docker context use orbstack and docker context use desktop-linux to switch between them at any time.


    Step 8: Repoint /var/run/docker.sock and Remove Leftovers

    Neither brew uninstall nor dragging the app to the Trash resets the system-wide socket. /var/run/docker.sock is a root-owned symlink that Docker Desktop created, and it keeps pointing at Docker Desktop’s socket after the app is gone.

    ls -l /var/run/docker.sock

    /var/run/docker.sock -> /Users/<you>/.docker/run/docker.sock

    The docker CLI does not notice, because the orbstack context talks to ~/.orbstack/run/docker.sock directly. What breaks are the tools that ignore Docker contexts and open /var/run/docker.sock on their own, such as Testcontainers, kind, and IDE Docker plugins. They fail with Cannot connect to the Docker daemon at unix:///var/run/docker.sock. Repoint the symlink to OrbStack.


    brew uninstall --cask docker also unloads and deletes Docker Desktop’s privileged helpers, but dragging the app to the Trash leaves them installed and running. The VM data directory is removed only by --zap. Clean up whatever remains, along with the now-dead context.

    # Privileged helpers
for s in com.docker.vmnetd com.docker.socket; do
  sudo launchctl bootout system/$s 2>/dev/null
done
sudo rm -f /Library/LaunchDaemons/com.docker.{vmnetd,socket}.plist \
           /Library/PrivilegedHelperTools/com.docker.{vmnetd,socket}

# Dead context and leftover VM data
docker context rm desktop-linux
rm -rf ~/Library/Containers/com.docker.docker
    💡 Tip

    rm may report Operation not permitted on ~/Library/Containers/com.docker.docker. macOS protects the container's metadata file, so only that few-KB file remains, and the VM disk image is deleted. Check with du -sh ~/Library/Containers/com.docker.docker.

    OrbStack Key Commands

    OrbStack supports all existing Docker commands and provides additional orb commands for extended functionality.

    # Standard Docker commands (unchanged)
docker build -t myapp .
docker run -d -p 8080:80 myapp
docker compose up -d
docker images
docker volume ls

# OrbStack-specific commands
orb status              # Check OrbStack status
orb start / orb stop    # Start/stop OrbStack
orb docker migrate      # Migrate Docker Desktop data

# Linux VM management (OrbStack exclusive)
orb create ubuntu       # Create Ubuntu VM
orb shell ubuntu        # Access VM shell

# Context switching (when running both)
docker context use orbstack       # Switch to OrbStack
docker context use desktop-linux  # Switch to Docker Desktop


    Troubleshooting


    BuildKit Container Migration Failure

    A No such image: moby/buildkit:buildx-stable-1 error may appear during migration. BuildKit containers are automatically recreated by docker buildx, so this can be safely ignored.

    # Verify buildx builders
docker buildx ls


    Docker Context Not Switching

    # Manually select OrbStack context
docker context use orbstack

# Verify
docker context ls


    CLI Tools Pointing to Docker Desktop

    # Remove Docker Desktop CLI symlinks
sudo rm -f /usr/local/bin/docker
sudo rm -f /usr/local/bin/docker-compose
sudo rm -f /usr/local/bin/docker-credential-desktop

# Restart OrbStack to reinstall CLI tools
osascript -e 'quit app "OrbStack"'
open -a OrbStack

# Verify
which docker
# Expected: ~/.orbstack/bin/docker or OrbStack.app path


    Tools Cannot Connect to /var/run/docker.sock

    docker ps works, but Testcontainers, kind, or an IDE plugin reports Cannot connect to the Docker daemon at unix:///var/run/docker.sock. The system socket still points at the removed Docker Desktop. See Step 8.

    sudo ln -sfn "$HOME/.orbstack/run/docker.sock" /var/run/docker.sock


    Buildx Imagetools Insecure Registry Error

    When using docker buildx imagetools create in OrbStack, you may encounter the following error:

    ERROR: failed to do request: Head "https://harbor.your-domain.com/v2/...": tls: failed to verify certificate: x509: certificate signed by unknown authority

    The Docker daemon’s insecure-registries setting only applies to regular docker push/pull operations. Since buildx uses a separate BuildKit container, it does not read that configuration. Docker Desktop forwards this setting automatically, but OrbStack requires manual configuration.

    Create a buildkitd.toml file and set up a new builder:

    Once the builder is created, it persists across sessions — no additional configuration is needed.


    Insecure Registries Not Migrated

    If insecure registry settings are missing after migration, add them manually through OrbStack settings.

    OrbStack → Settings → Docker → Advanced → Edit daemon.json

    {
  "insecure-registries": [
    "harbor.your-domain.com"
  ]
}


    Conclusion

    Migrating from Docker Desktop to OrbStack takes roughly five minutes. A single orb docker migrate command handles the transfer of containers, images, volumes, and daemon configuration automatically, while maintaining full Docker CLI compatibility — resulting in virtually zero transition cost.

    The most noticeable improvements in daily use are reduced CPU and memory consumption, significantly faster startup times, and extended battery life on MacBook devices. For developers spending their day running containers, OrbStack represents a meaningful quality-of-life improvement.
