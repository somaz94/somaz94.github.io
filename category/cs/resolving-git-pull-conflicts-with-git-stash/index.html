    Resolving Git Pull Conflicts with Git Stash

    A practical guide to safely stashing, pulling, and restoring local changes


    Overview

    When working on local files that have also been modified on the remote, git pull fails — a situation every developer encounters sooner or later.

    error: Your local changes to the following files would be overwritten by merge:
        .github/workflows/ci.yml
Please commit your changes or stash them before you can merge.

    git stash provides a clean way to temporarily shelve uncommitted local changes, pull remote updates without conflict, and then restore your work on top of the updated codebase.

    This post walks through the stash → pull → stash pop workflow, explains what happens at each step, and covers how to handle conflicts that may arise during restoration.


    What is Git Stash?

    git stash temporarily saves your working directory’s uncommitted changes into a stack-based storage area and reverts the working directory to the last commit state.

    It is commonly used in the following scenarios.

    • Pull conflicts — Local changes collide with remote changes
    • Branch switching — Need to switch branches mid-work without committing
    • Clean state needed — Want a clean working directory temporarily without losing progress


    How the Stash Stack Works

    Working Directory (with changes)
    │
    ▼  git stash
Stash Stack (temporarily saved)
    │
    ▼  git stash pop
Working Directory (changes restored)

    The stash operates as a LIFO (Last In, First Out) stack. You can store multiple stashes and retrieve them in reverse order.


    The Problem: Pull Fails with Local Changes

    When you have uncommitted local changes and the remote has modified the same files, git pull refuses to proceed.

    $ git pull
error: Your local changes to the following files would be overwritten by merge:
        .github/workflows/ci.yml
Please commit your changes or stash them before you can merge.

    Git is protecting you from accidentally losing your local work. The solution is the three-step stash workflow.


    The Solution: Stash → Pull → Stash Pop


    Step 1: git stash — Save Local Changes

    $ git stash
Saved working directory and index state WIP on main: a1b2c3d ...

    This saves all uncommitted changes (tracked files) to the stash stack and resets the working directory to a clean state.

    Note: git stash only saves tracked files by default. To include untracked files, use git stash -u.


    Step 2: git pull — Fetch Remote Changes

    $ git pull
Updating a1b2c3d..d4e5f6g
Fast-forward
 .github/workflows/ci.yml | 5 +++--
 CHANGELOG.md              | 3 +++
 2 files changed, 6 insertions(+), 2 deletions(-)

    With the working directory clean, Git can now pull remote changes without any conflicts.


    Step 3: git stash pop — Restore Local Changes

    $ git stash pop
Auto-merging .github/workflows/ci.yml
On branch main
Changes not staged for commit:
  modified:   .github/workflows/ci.yml
  modified:   .github/workflows/deploy.yml
Dropped refs/stash@{0} (a1b2c3d...)

    This retrieves the stashed changes and applies them on top of the updated codebase. Git automatically attempts to merge your changes with the pulled updates.

    • If there are no conflicts, the merge succeeds silently.
    • pop removes the stash entry after successful restoration.


    Workflow Summary

    [Local changes + Remote changes] → pull fails
    ↓
git stash        → Save local changes (clean working directory)
    ↓
git pull         → Apply remote changes (no conflict)
    ↓
git stash pop    → Restore local changes (auto-merge)
    ↓
[Both changes applied successfully]


    Handling Conflicts During Stash Pop

    If the remote changes and your stashed changes modify the same lines, a merge conflict occurs during git stash pop.

    $ git stash pop
Auto-merging .github/workflows/ci.yml
CONFLICT (content): Merge conflict in .github/workflows/ci.yml

    Git leaves conflict markers in the file for manual resolution.

    <<<<<<< Updated upstream
  node-version: '20'
=======
  node-version: '18'
>>>>>>> Stashed changes


    Resolving the Conflict

    1. Open the conflicted file and choose the correct version (or combine both).
    2. Stage the resolved file.
    3. Manually drop the stash (it was not auto-deleted due to the conflict).
    # After resolving the conflict
git add .github/workflows/ci.yml

# Manually remove the stash entry
git stash drop

    Important: When a conflict occurs, pop does not complete fully, so the stash entry is not automatically deleted. You must run git stash drop manually after resolving.


    Useful Stash Commands Reference


    Command Description
    git stash Save changes (tracked files only)
    git stash -u Save changes including untracked files
    git stash list List all saved stashes
    git stash show -p Show stash contents in detail (diff)
    git stash pop Restore and remove from stash
    git stash apply Restore only (keep in stash)
    git stash drop Delete a specific stash entry
    git stash clear Delete all stash entries
    git stash branch <name> Create a new branch from stash contents


    pop vs apply: Choosing the Right Command

    The key difference between pop and apply is whether the stash entry is removed after restoration.

    • git stash pop — Restores changes and deletes the stash entry. Use this when you are confident the restoration will succeed.
    • git stash apply — Restores changes but keeps the stash entry. Use this when you want to verify the result before deleting.

    Tip: Using git stash apply followed by git stash drop after verification is a safer alternative to git stash pop, especially when dealing with complex merges.


    Conclusion

    git stash is a simple yet powerful tool that comes in handy in everyday development workflows. Whether you need to resolve pull conflicts quickly or switch branches mid-work, the stash → pull → stash pop pattern is all you need to remember.

    Even if conflicts occur during stash pop, Git provides clear conflict markers (<<<<<<<, =======, >>>>>>>) that make manual resolution straightforward.
