문제

전체 인프라를 AWS 단일 환경에서 운영하며 클라우드 비용 부담이 컸습니다. 트래픽 변동이 적은 비프로덕션 환경까지 클라우드 리소스를 상시 점유하고 있어 비용 최적화와 환경 분리가 필요했습니다.

접근 전략

  • 하이브리드 아키텍처 설계 - 워크로드별 비용 및 사용 패턴을 분석해 dev·qa 환경은 온프레미스로 전환하고, 확장성과 고가용성이 필요한 review·prod 환경은 AWS에 유지
  • 네트워크 및 파이프라인 격리 - 복잡한 사이트 간 VPN 구성 없이 애플리케이션 레벨에서 트래픽을 분리하고, 이미지 레지스트리도 이원화(dev·qa=Harbor, review·prod=ECR)하여 환경별로 독립적으로 빌드·운영
  • IaC 기반 운영 표준화 - 온프레미스와 AWS 전반에 Terraform과 Ansible을 도입해 신규 컴포넌트 IaC 100%를 달성하고, 이종 인프라 환경에서도 일관된 형상 관리 체계 수립
  • IAM 자격증명 거버넌스 - 서비스·CI 계정만 코드로 관리하고 콘솔 계정은 분리. Terraform state 파일에 장기 자격증명(액세스 키)이 평문으로 남지 않도록 사용자 키 자동 생성을 배제하고 개별 발급·회전 정책 적용

문제

접근 전략

  • GitOps 기반 지속 배포(CD) 파이프라인 구축 - GitLab CI와 ArgoCD를 연계해 Git Push를 트리거로 빌드 → 테스트 → 배포 전 과정을 자동화하고, Git에 선언된 형상과 클러스터 상태 간 불일치를 감지해 자동 복구(Self-healing)하도록 구성. dev·qa·review·prod 4개 환경의 배포 로직을 단일 파이프라인으로 통합해 관리 일관성 확보
  • 최소 권한 기반의 안전한 이미지 빌드 환경 수립 - Docker-in-Docker(DinD) 방식에서 요구되는 호스트 관리자 권한(Privileged 모드) 부여를 배제하기 위해, 도커 데몬 없이 사용자 영역(User-space)에서 컨테이너 이미지를 빌드하는 Kaniko를 도입해 CI 러너의 보안 취약점과 권한 탈취 리스크를 원천 차단

트러블슈팅

  • ArgoCD 연쇄 삭제(cascading prune) 방지 - Git 커밋 오류로 하위 Application 전체가 연쇄 삭제되는 사고를 방지하기 위해, 워크로드 Application은 prune: true + selfHeal: true로 자동 일치시키고 최상위 app-of-apps 루트·AppProject 계층은 prune: false로 두어 리소스 삭제는 수동 검증을 거치도록 통제. 모든 sync 이벤트는 Slack 알림으로 실시간 추적
  • 정적 데이터 배포 경로에서 SSH 키 제거 - CI 배포 계정이 SSH 키를 상시 보유한 채 대상 인스턴스에 직접 접속(scp/rsync)하던 구조를, 산출물을 S3 중계 버킷에 올리고 SSM SendCommand로 인스턴스가 스스로 내려받는 방식으로 교체 — 배포 환경의 정적 SSH 키를 완전히 제거해 자격증명 유출 리스크 차단

문제

GitLab CI 표준화 대상 repo마다 각 잡이 alpine 베이스에 helm·helmfile·kubectl·crane·aws-cli를 매번 설치해 빌드 환경 프로비저닝에 평균 5분이 걸렸고, 도구 버전이 consumer repo마다 흩어져 신버전 추가 시 모든 repo를 손대야 했습니다. :latest 의존으로 재현성과 취약점 추적도 어려웠습니다.

접근 전략

  • Layer 1 (Mirror) - 외부 레지스트리(Docker Hub, GHCR)의 도구 이미지를 multi-arch manifest(여러 CPU 아키텍처를 묶은 이미지 목록)는 보존한 채 crane copy로 사내 Harbor에 미러링
  • Layer 2 (Custom) - Layer 1 위에 도구를 미리 설치해 둔 이미지(helmfile-tools, base-tools, node-build, rclone-backup, aws-cli-tools)를 빌드해 consumer repo가 image pin만으로 도구를 즉시 쓰도록 표준화
  • Tier 1~2 SSOT(단일 관리 기준) - .toolchain_build_custom 공용 템플릿 + TOOLCHAIN_*_TAG 중앙 변수를 도입해 consumer repo가 image tag를 직접 추적하지 않도록 전환
  • 공용 CI 템플릿 SSOT - repo마다 복사해 쓰던 CI 잡을 공용 템플릿 repo로 추출해 include로 참조. auth(정적 키 없는 AWS 인증) / build(kaniko) / deploy(ArgoCD) / backup(Google Drive) 잡 템플릿과 공용 앵커(git·ssh·rules·job-config·packages)를 한곳에서 관리해 복사본 간 설정 드리프트 제거
  • 자동 버전 사이클 - 주간 스케줄이 (1)을 돌리고, 사람이 파이프라인을 실행하면 (2)~(4)가 자동 MR로 이어짐. 사람의 판단 지점은 파이프라인 실행과 Tier 2 MR 머지 두 곳:
       · (1) upstream 신버전 감지
       · (2) Layer 1 mirror auto-MR
       · (3) Layer 2 rebuild + Tier 2 TOOLCHAIN_*_TAG 동기화 auto-MR
       · (4) consumer repo(template provider repo 제외)에 자동 전파

트러블슈팅

  • 자동 버전 상향 중 helmfile 1.5.1이 helm 3.18.6 이상을 요구하는데 helm은 3.16.4에 고정돼 있어 build_custom 빌드가 깨짐. 도구 간 호환 요구사항은 upstream 릴리스 노트로만 알 수 있어 자동 감지가 불가능하다고 판단, helm·helmfile·kubectl에 minor-guard를 도입해 현재 minor 안의 patch만 자동 상향하고 minor·major는 사람이 호환성을 확인한 뒤 올리도록 분리(*_TARGET_MINOR 환경변수로 계획된 minor bump 시 1회 override)

성과

  • CI 빌드 환경 프로비저닝 시간 5분 → 약 10초 (약 95% 단축), 사내 repo 전반에 도구 버전 일관성 100% 확보, 버전 거버넌스 4-tier(ARG → 중앙 변수 → consumer 분리 → lint drift 감지)로 흩어져 있던 버전 지정 지점을 한 흐름으로 정리

신규 퍼블리싱 게임이 퍼블리셔 내부 인증 계정과 통신해야 했고, 이 구간은 공용 인터넷을 경유할 수 없어 VPC 피어링을 통한 사설 경로가 요구되었습니다. 그런데 기존 프로덕션 VPC의 대역이 피어링 요건과 맞지 않아 VPC와 그 위의 클러스터·데이터 계층까지 전면 재생성이 불가피했고, 재구축되는 클러스터는 퍼블리셔의 요청에 따라 EKS Auto Mode로 구성해야 했습니다. 기존 클러스터는 관리형 노드그룹 위에 Karpenter를 직접 운영하는 구조라 컴퓨트 영역의 Terraform·state 관리 포인트가 비대했고, 노드 수명주기·스팟 중단·핵심 애드온을 직접 관리하는 오버헤드도 컸습니다. 또한 VPC 피어링은 중계 라우팅을 지원하지 않아(non-transitive) 온프레미스에서 AWS 내부 ALB(private)로 가는 사설 경로는 별도로 확보해야 했습니다.

접근 전략

  • EKS Auto Mode 기반 컴퓨트 계층 관리형 전환: 노드 프로비저닝, 수명주기 관리, Karpenter 부속 리소스(IAM·SQS·EventBridge) 및 내장 애드온(LB Controller·EBS CSI)을 AWS 완전 관리형으로 이관하고 선언적 NodePool만 유지하여 인프라 코드 복잡도 대폭 경감
  • IPAM 제약 대응 플랫폼 재설계(Re-platforming): 가용 서브넷 확장 불가 제약(/20 4개가 상위 /18을 정확히 소진)에 맞춰, 서브넷 물리 분리 대신 단일 private 서브넷 내 보안 그룹(Security Group) 기반 논리 격리 아키텍처로 전환(Aurora·Valkey·EFS 재배치)
  • 동적 공인 IP(DDNS) 대응 Site-to-Site WireGuard VPN 구축: 사무실 공인 IP가 유동이라 고정 IP가 필수인 AWS 관리형 VPN(Customer Gateway) 도입이 불가함에 따라, 온프레미스에서 AWS(EIP) 방향 아웃바운드 터널을 수립하고 peer endpoint를 의도적으로 비워 첫 핸드셰이크 패킷으로 변경된 IP를 자동 추적하는 게이트웨이 설계
  • 플랫폼 컴포넌트 호환 마이그레이션: 관측성·보안·CI 툴체인 등 16개 핵심 플랫폼 컴포넌트를 Auto Mode 사양에 맞게 재구성하고, 10개 컴포넌트를 ArgoCD Pull-GitOps 관리 체계로 전환

트러블슈팅

  • Auto Mode 시스템 테인트로 인한 부트스트랩 순환 교착 해소: 기본 system NodePool의 CriticalAddonsOnly 테인트 때문에 자체 워크로드 노드가 프로비저닝되기 전까지 일반 Pod 용량이 0이라 ArgoCD Pod부터 Pending으로 멈추는 데드락 발생. NodePool·IngressClass 매니페스트를 GitOps 트랙에서 분리해 helmfile 기반 사전 부트스트랩 단계에서 선제 배포하도록 배포 순서 재정립
  • IngressClass 누락에 따른 로드밸런서 미생성(silent failure) 해결: AWS Load Balancer Controller Helm 차트가 프로비저닝하던 IngressClass가, 컨트롤러를 내장한 Auto Mode에는 그 차트가 없어 만들어지지 않음. ingressClassName: alb를 명시해도 매칭되는 컨트롤러가 없어 에러 로그도 없이 로드밸런서가 생성되지 않는 현상을 식별하고, Auto Mode 전용 IngressClass를 독립 컴포넌트로 정의해 클러스터 생성 직후 선행 배포
  • NodeClass API 그룹 변경 및 미지원 애드온 분리: Auto Mode에서도 NodePool 작성은 그대로지만 NodeClass의 API 그룹이 karpenter.k8s.aws/v1 EC2NodeClass에서 eks.amazonaws.com/v1 NodeClass로 바뀌어 기존 매니페스트가 호환되지 않음. 스펙을 신규 CRD에 맞춰 재작성하고, Auto Mode가 내장하지 않는 EFS CSI Driver는 배포를 별도로 분리

주요 성과

  • 컴퓨트 계층 Terraform 관리 포인트를 102개 → 17개로 83% 감축하고, 노드 수명주기·스팟 회수 오버헤드를 AWS 완전 관리형으로 이관
  • 온프레미스·AWS 간 Site-to-Site VPN 게이트웨이로 내부 ALB를 공용 인터넷에 노출하지 않고 단일 내부 호스트명·단일 TLS 인증서 유지 — 대안인 환경별 public ALB 추가는 환경이 늘 때마다 이름·인증서·DNS 레코드가 두 배가 되어 기각
  • 부분 장애(gray failure)를 차단하는 fail-fast 라우팅 — 정적 라우트를 Pod·노드 단위가 아닌 게이트웨이 라우터 단일 지점에 두어 경로가 사라지면 전체가 한 번에 실패하도록 구성(노드마다 두면 같은 서비스의 동작 여부가 Pod 배치에 따라 갈림)
  • 터널이 Terraform 밖에서 의존하는 세 가지(라우터 정적 경로·게이트웨이 설정 파일·개인키)를 런북에 명시해 terraform plan에 보이지 않는 의존을 드러내고, 개인키는 여러 사람이 읽는 state 버킷에 평문으로 남지 않도록 SSM Parameter Store SecureString으로 완전 분리

문제

AWS 비용이 지속 상승했고, 특히 상시 가동되는 게임 워크로드를 Fargate로 돌리며 발생하는 Pod 단위 과금이 큰 비중이었습니다. 비용 절감과 멀티 리전 게임 서비스를 위한 글로벌 로드밸런싱 확보를 목표로 GCP 마이그레이션을 추진했습니다.

접근 전략

  • 3단계 순차 이전 - 1단계 개발 환경 GCP 구축·검증, 2단계 QA, 3단계 프로덕션
  • 네트워크·인증 - Shared VPC(Host Project / Service Project 분리) 설계, GitHub Actions의 GCP 인증은 Workload Identity Federation으로 전환해 서비스 계정 키 발급·순환을 OIDC 단기 토큰으로 대체. DNS는 서브도메인 위임(Hosting.kr → AWS Route53 → GCP Cloud DNS)으로 사전 검증하고, 최종 NS 변경만 점검 공지 후 cutover
  • 컴퓨트 재배치 - AWS Fargate 워크로드를 GKE 표준 노드 풀로 이전. 상시 워크로드는 Pod 단위 과금이 VM 단위보다 불리해 동일 과금 구조인 GKE Autopilot 제외

  • IaC·GitOps 파이프라인 - Terraform으로 GCP 인프라 IaC화(IAM 제외 100%), 이전 후 GitLab CI + ArgoCD GitOps CI/CD 파이프라인 구축, Helm Chart로 환경별 설정 표준화

  • Cloud CDN 마이그레이션 후 HTTP → HTTPS 리다이렉트 누락으로 게임 클라이언트 파일 다운로드 실패. URL Map을 HTTP / HTTPS 두 개로 분리(default_url_redirect.https_redirect=true)하고 HTTP forwarding rule에 80 포트 target HTTP proxy를 별도 매핑하여 해결
  • Cloud DNS 위임 후 Google Search Console에 도메인이 자동 등록되지 않아 검색 노출·소유권 확인 문제 발생. Search Console verification TXT 레코드를 Cloud DNS에 추가해 소유권 검증 후 재등록

  • BigQuery 결과를 Google Sheets API로 적재할 때 단일 시트 1천만 셀 한도·쓰기 쿼터와 분당 요청 한도(429)에 걸려 갱신 실패. values.batchUpdate 청크 분할과 시트 분할로 셀 한도를 우회하고, 호출 pacing(throttle)·배치 처리·지수 백오프로 쿼터 내에서 동작하도록 구현
